# Feedback and Revision Route

This is a pilot scholarly workflow. Feedback should identify the exact release,
artifact, benchmark, and observed behavior.

- [Report a problem](https://github.com/pedahzur/from-question-to-evidence/issues/new?template=lab-problem.yml)
  when an instruction is ambiguous, a benchmark fails, a source is fabricated, a
  permission boundary is crossed, or the package cannot be used as documented.
- [Propose a revision](https://github.com/pedahzur/from-question-to-evidence/issues/new?template=lab-revision.yml)
  when suggesting a methodological, pedagogical, accessibility, or maintenance
  improvement.

Do not attach participant data, credentials, restricted archival material,
confidential manuscripts, or copyrighted full text. Use a synthetic or redacted
reproduction when possible.

Every accepted change should name the evidence or benchmark that justifies it,
record the human decision, update the package version when behavior changes, and
remain visible in the project changelog.
